# Veil 1.0.1 — Repository Polish Design

**Date:** 2026-06-14
**Status:** Approved
**Type:** Documentation / repository polish (no public API change)

## Goal

Bring the `Moongazing.Veil` repository up to the same presentation and community-health
standard as the Orion family (OrionKey, OrionGuard, OrionAudit, OrionLock, OrionPatch), and
cut a `1.0.1` patch release. No production code changes — this release is purely about making
the project clearer, easier to contribute to, and consistent with its siblings.

## Context

- Current version: `1.0.0`, not yet published to NuGet.
- Three packable projects: `Moongazing.Veil`, `Moongazing.Veil.AspNetCore`, `Moongazing.Veil.Serilog`.
- README is already strong, but several GitHub links point at the wrong repo
  (`tunahanaliozturk/Moongazing.Veil` and `/blob/main/`). The real remote is
  `github.com/tunahanaliozturk/Veil` and the default branch is `master`.
- Missing community-health files that every Orion package has: `CONTRIBUTING.md`,
  `CODE_OF_CONDUCT.md`, `SECURITY.md`, `.github` templates, a standalone `docs/ROADMAP.md`.

## Scope

### 1. Community-health files (new, English, Orion style)

- **`CONTRIBUTING.md`** — adapted from OrionKey's, Veil-specific: how to add a pattern, a
  locale, an integration; test conventions (xUnit + FluentAssertions); analyzer-warnings-as-errors;
  Conventional Commits; "open an issue first for non-trivial changes".
- **`CODE_OF_CONDUCT.md`** — Orion's short, readable version.
- **`SECURITY.md`** — responsible disclosure. Extra emphasis appropriate for a masking/PII
  library: how to report a masking bypass or data-leak class of bug privately, supported
  versions table, no public issues for vulnerabilities.

### 2. `.github/` templates

- `ISSUE_TEMPLATE/bug_report.yml`, `ISSUE_TEMPLATE/feature_request.yml`, `ISSUE_TEMPLATE/config.yml`
- `PULL_REQUEST_TEMPLATE.md`
- `FUNDING.yml`
- `dependabot.yml` (NuGet + GitHub Actions, weekly)

### 3. `docs/ROADMAP.md`

Move the README's inline roadmap into a standalone `docs/ROADMAP.md` in the Orion format:
status legend, phase sections, "Considered (no commitment)", "Out of scope", a release-cadence
table, and a contributing/feedback footer. README keeps a short roadmap summary that links out.

### 4. README improvements

- Add a **"More from the Orion family"** cross-link section.
- Slim the Contributing section to link `CONTRIBUTING.md` + `CODE_OF_CONDUCT.md`.
- Replace the long inline roadmap with a short summary + link to `docs/ROADMAP.md`.
- Fix all broken GitHub URLs: `tunahanaliozturk/Moongazing.Veil` → `tunahanaliozturk/Veil`,
  `/blob/main/` → `/blob/master/`. NuGet package URLs (`nuget.org/packages/Moongazing.Veil`)
  stay unchanged — that is the package id, which is correct.

### 5. Version bump to 1.0.1

- Centralize `<Version>1.0.1</Version>` into `Directory.Build.props` and remove the per-project
  `<Version>` duplication from the three src csproj files (test/sample projects are
  `IsPackable=false`, so a shared version is harmless).
- Add `<PackageReleaseNotes>` pointing at the changelog.
- Add a `[1.0.1]` entry to `CHANGELOG.md` (Changed: docs/repo polish; Fixed: repository URLs).
- Fix repo URLs in `Directory.Build.props`, `CHANGELOG.md`, and the three `docs/*.md` NuGet
  readme image links.

## Out of scope

- No new patterns, locales, or integrations.
- No OpenTelemetry / source-generator work (those remain roadmap items for 3.x).
- No public API changes — this stays a clean patch release.

## Verification

- `dotnet build -c Release` and `dotnet test` both pass.
- All GitHub links resolve to `tunahanaliozturk/Veil`.
- `dotnet pack` produces three packages stamped `1.0.1`.
